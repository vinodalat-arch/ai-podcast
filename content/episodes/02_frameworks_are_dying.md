### Builds on: Episode 1 — Code is Becoming Cheap

> "For 20 years, software engineering optimized one thing: making it easier for humans to write code. Frameworks were the answer. Today, AI writes most of that code in seconds. So what exactly are frameworks solving anymore?"

Frameworks optimized human effort in writing code. AI removes that constraint entirely. Boilerplate reduction, generic abstractions, framework-driven standardization — all losing value fast.

If Episode 1 showed that code is cheap and trust is expensive, this episode asks the obvious follow-up: what happens to the tools we built to make coding easier?

The answer isn't that frameworks disappear. It's that their original purpose does. Most organizations are still investing in framework-heavy architectures designed for a world where humans were the bottleneck. That world is gone.

What replaces them: context systems, agent primitives, validation systems, and execution harnesses. The old model (Framework → Code → Runtime) gives way to a new one (Context → Agent → Generated Code → Validation → Runtime).

Frameworks die where they exist to reduce coding effort. They survive where they enforce correctness.
